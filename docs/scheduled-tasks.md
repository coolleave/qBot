# 定时任务与问候文案

当前是单进程按星期和时间触发的消息调度，支持早午晚及其他文案时段，不是通用 cron 系统；真实 QQ 主动发送待验收。导航见 [文档索引](README.md)。

## 配置与入口

在「定时任务 → 新建任务」选择机器人，从已绑定接收人列表搜索姓名或完整 OpenID、分页选择用户，直接打开任务表单，无需进入聊天记录。选择对象始终创建独立任务，不受已有任务限制；已有配置从任务列表进入编辑。接收人来自「用户与群备注」，私聊发给本人、群聊发给整个群；新建时填写名称并选择 morning / noon / evening / other 文案时段，每条任务单独配置：启用、发送时间、星期和 1～200 字固定文案。发送模式可选文字、文字＋图片、语音＋图片和预设 1 / 2；语音＋图片需要启用的 TTS 供应商和音色，文案即朗读内容。

北京时间 UTC+8，星期为 1～7。默认发送时间为早间 07:00、午间 12:00、晚间 21:00，默认关闭。取消最晚执行时间和窗口重叠限制，各任务分别按日去重，可设置相同时间。

## 扫描与每日领取

每轮最多扫描 100 条当前分钟到期且当天未领取任务，逐条发送，结束后等待 10 秒；发送耗时影响执行时间，不保证精确到秒。只领取当前设定分钟的任务，且配置须在该分钟开始前保存；服务错过该分钟不补发。

自动调度调用 claim_scheduled_greeting，在事务中锁定、复核规则与接收人，同时创建独立聊天记录和每日领取记录。唯一范围包含机器人、任务和北京时间日期。领取后才检查机器人运行与限流，因此未运行、限流、失败、送达未知都会消耗当天次数，不自动重试。修改配置、重启或 `/reset` 不清除当天领取。

定时与手动发送共享主动限流和 BotManager 锁；组合消息的每一部分各占一次主动限流额度。媒体准备总预算100秒，单条 QQ 发送预算25秒。文字模式的固定文案不调用模型、不进入聊天上下文、不携带旧 msg_id。私聊发给用户，群聊发给全群；同群不同成员会话分别配置会重复发群消息。

解除接收人名称绑定或更换机器人 AppID 会停用相关任务。中断留下的 processing 记录不重放。表名仍为 interaction_greetings / interaction_greeting_runs，但任务已不依赖用户聊天触发。

## 执行一次与生成草稿

「执行一次」使用已保存配置（固定模式使用已保存文案，预设 1 / 2 现场选图并生成），跳过启用、星期和发送时间限制；仍检查接收人、运行状态和限流，每次点击新建一次独立执行，不占用或受限于自动任务的当天额度。相同任务可反复手动发送；请求结果不明时先查记录，再点击会再次发送。

「按人设生成文案」读取最新保存的人设及聊天供应商，私聊可参考姓名和角色，群聊面向全群。返回草稿后需保存；生成不保存任务、不发送、不占每日次数、不进入聊天上下文，不会每天自动重新生成。

生成可能收费，最多一次模型调用、不自动重试；模型超时 30 秒，生成预算 35 秒；后台同一时间最多生成一条，开始间隔至少 10 秒。失败保留原草稿。输出预算1024 token，百炼 Qwen 沿用模型默认思考设置，不传 enable_thinking 参数；超长正文优先在200字内完整句末裁剪，否则省略号截断。空正文、超时、鉴权、模型不存在、限流等分别提示，日志只记录安全状态码/异常类型。旧版统一错误无法反推出当时实际原因，新版需重试查看具体提示。

## 组合消息与图片保存

迁移 `0013_greeting_media` 增加 delivery 配置、image_data 二进制及 image_filename，旧任务默认保持文字。上传 PNG/JPG 单张不超过3.5 MB，按机器人及会话校验权限；图片随任务配置存库以供定时执行，直到显式替换或删除。读取任务只返回文件名和是否存在图片，不返回 Base64。切换回文字会保留已上传图片，需要移除时勾选删除；手动组合模式必须有图片，预设 1 / 2 使用本地素材无需上传。语音任务引用的 TTS 不能直接停用或改类型。

文字＋图片是先发文字、再发图片；语音＋图片先发语音、再发图片，私聊语音转 SILK。每次语音任务执行时合成一次文案（固定文案或 AI 生成结果），会产生TTS费用，不受聊天自动语音开关控制。先完成所有媒体准备和上传，再执行发送；准备失败不发送任何部分，语音失败不擅自改发文字。两条是独立 QQ 消息，不保证原子送达，也不是一张图文卡片。

发送前后保存每部分状态到聊天记录 media_details.parts，全部确认才标记 replied；部分失败显示已确认数量，发送超时标为 delivery_unknown，剩余部分不继续，不自动补发。自动任务沿用每天一次规则；手动执行每次独立记录，不占自动额度。重启后不恢复未完成组合，先核对实际送达再作处理。

## 可组合流程与模板配置

定时消息现在使用配置驱动的线性流程，后台可「套用模板」或直接修改三个选项：

| 选项 | 支持值 |
| --- | --- |
| 文案来源 content_source | fixed 固定文案 / ai 每次执行生成 |
| 图片来源 image_source | none 不带图 / upload 上传图片 / library 素材库随机图 |
| 输出 output | text 文字 / audio TTS 语音 |

素材库随机图需选 library_id，语音输出需选 TTS 供应商和音色。可组合出 AI 纯文字、AI 纯语音、固定文案＋随机图片等；上传图片不调用视觉模型，AI 仅在使用素材库时参考清单里的图片描述。模板与素材库由 `config/scheduled_templates.json` 定义，前端通过鉴权的原任务读取接口返回的 catalog 动态展示，不在页面或执行器枚举预设编号。

预设 1 是 ai + library(kittens) + text，预设 2 是 ai + library(kittens) + audio。新增同类模板只需在配置文件 templates 中添加唯一 id、name、workflow；新增素材库在 libraries 添加唯一 id、name、manifest（项目内相对路径），清单沿用 items / status=ready / image / pose_description 格式，图片必须位于清单同目录。不需要修改执行器或前端。配置文件不是业务提示词，客户端不能提交素材清单路径。

统一流程顺序：领取当天额度 → 复核运行状态及限流 → 可选选图 → 固定文案或 AI 生成 → 可选图片上传和 TTS 准备 → 发送文字/语音 → 可选发送图片 → 保存结果。任务配置和每次执行均保留 workflow 快照；同一次执行使用领取时解析的流程，不按模板编号分支。生成、媒体、发送期限及失败不重试策略保持不变。

数据复用 delivery JSON，新增 workflow={version:1, content_source, image_source, output, library_id, prompt_style}，无新迁移。旧任务未保存 workflow 时通过模板目录转换，原五个模板 ID 应保留；重新保存后使用独立快照，改模板不会改变这些已保存任务的组合，素材库内容仍按当前清单读取。TTS 供应商引用检查按 output 判断，含自定义流程。

核心代码：`greeting_workflows.py` 校验与兼容转换，`greeting_presets.py` 素材读取，`proactive.py` 通用执行。部署需带上 config 目录及素材。当前是固定顺序、可组合的消息流程，不支持任意拖拽节点、条件分支、循环或第三方工作流引擎；增加全新能力（如视频）仍需实现对应处理步骤。现有被动聊天、ASR、视觉理解链路未改为此流程。只完成静态与配置校验，未运行测试或真实发送验收。

## 语音文案风格（已实现，待真实试听）

AI 生成节点依据 workflow.output 区分文字和语音。语音文案只输出可直接朗读的自然口语，不写中文或英文括号里的动作、神态、心理描写，也不写星号动作旁白。已进一步取消动作自述：不输出“从纸箱里探出脑袋”或“我正在伸懒腰”等角色表演，只结合图片氛围直接问候。该要求替代此前将动作转成第一人称的做法。音频首尾静音与短淡入淡出复用统一 TTS 处理，详见多模态文档。

这项约束适用于所有 AI 文案＋TTS 的组合，不依赖预设编号。文字输出不追加语音专用提示，手动保存的固定文案不自动改写。提示词放在独立业务提示词文件，模块文档及 AGENTS.md 不传给模型。业务提示词为 `qbot/prompts/greeting_audio.txt`；已通过 Python AST 静态检查，未运行测试或调用真实模型、TTS，生成效果和试听待验收。
