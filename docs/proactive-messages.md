# 后台主动发送

导航见 [文档索引](README.md)。每日任务领取单独见[定时任务](scheduled-tasks.md)。

## 使用边界

从「对话」（原发送消息）或聊天记录详情选择已有 QQ 接收对象。服务端依据记录确定目的地，检查 bot_id、管理员、CSRF、机器人运行状态，不接受任意 QQ 号。私聊发给用户，群聊发全群。

文字不调用模型、不写内存上下文。主动发送不带旧 msg_id，受 QQ 权限、额度、接收范围和内容限制，不能通过按钮绕过。

## 代码和接口

| 位置 | 职责 |
| --- | --- |
| [proactive.py](../qbot/proactive.py) 的 ProactiveSender.send | 运行状态、目的地、限流、幂等与发送 |
| [media.py](../qbot/media.py) | 文件头、类型、体积校验及摘要 |
| [qq.py](../qbot/qq.py) | send_proactive、upload_media、send_media |
| [audio_codec.py](../qbot/audio_codec.py) | 私聊 WAV 转 SILK |
| [admin.py](../qbot/admin.py)、[admin.js](../qbot/static/admin.js) | API 与页面交互 |

POST `/api/admin/bots/{bot_id}/records/{record_id}/send` 接收 content、UUID request_id；文字受 MAX_REPLY_CHARS 限制。相同前缀下 `/send-media` 接收原始文件字节，查询参数 kind、filename、request_id。

媒体单文件最多 3,500,000 字节，限制读取量和上传时间，不接受任意路径/URL。图片 PNG/JPG；群语音 SILK/MP3/WAV，私聊 SILK，受支持 PCM WAV 自动转码。无录音功能。

## 幂等与阶段

发送期间持有 BotManager.lock，避免启停替换凭证；手动和定时共用主动每目标/全局限流，与被动接收独立。

先以 `admin-send:` 加 request_id 创建独立记录，按数据库机器人及会话范围去重。重复请求返回原结果，不再发送；同标识用于不同内容报冲突。网络出错前端保留标识，不能每次重试都换 ID。

先保存 answer，再发送：QQ 确认是 replied，拒绝是 send_failed，最终发送超时/网络异常是 delivery_unknown。中断留下的待处理记录不重放；核对 QQ 后再决定是否创建新请求。

媒体先以 srv_send_msg=false 上传 users/groups files，预算 60 秒，再以 msg_type=7 和 file_info 发送，预算 25 秒。上传失败尚未执行发送，上传成功不代表送达；file_info 不跨机器人或来源缓存。

## TTS 与数据保留

默认音色（已实现，待界面验收）：每次打开编写消息窗口，按接收对象所属机器人的 `multimodal.voice` 初始化音色；未配置时使用 Bunny。发送消息列表和聊天记录详情入口共用此行为，可临时修改，不回写机器人配置。保存机器人配置后，下次打开窗口采用新配置；不同机器人之间不沿用上次填写的音色。已通过 JavaScript 语法及差异静态检查；按约定未运行测试、打开浏览器或调用真实 TTS。

语音窗口可选启用的 TTS 生成 WAV 试听，发送复用音频，不再次合成；修改文本、音色、供应商需重新生成。私聊 WAV 经隐藏子进程转 SILK，15 秒预算、不重试；支持单声道 16 位 PCM、8/12/16/24 kHz，不支持私聊 MP3。协议及自动回复策略见[多模态](multimodal.md)。

记录保存文件名称、大小、摘要及 SHA256，不存原文、Base64、file_info、临时地址，不支持历史重新下载。去重仍按原始 WAV 摘要。排查时区分校验、转码、上传与最终发送。本次未上传或发送文件，真实平台验收待完成。

## QQ 拒绝发送的诊断

发送/媒体上传被拒绝时，记录固定阶段说明、HTTP 状态、QQ 业务错误码及请求标识，供后台排查；不保存响应原文、消息内容、Token 或完整 URL。旧记录若只有笼统错误，无法追溯平台实际原因，不能直接断言为额度或权限。网络超时和 5xx 继续记送达未知，不自动重发。

## 对话页面（已实现，交互待验收）

原「发送消息」改为「对话」：机器人选择、私聊/群聊 Tab、左侧会话列表与搜索、右侧历史气泡及底部文字输入。私聊按 bot_id + user_id 读取，群聊按 bot_id + group_id 汇总各成员的已记录发言并标记成员；不改变模型上下文隔离，只展示数据库中平台推送并已保存的消息。按 ID 向前分页加载更早记录，当前会话停留底部时每 10 秒刷新最新记录。

新增鉴权 GET `/api/admin/bots/{bot_id}/records/{record_id}/messages?before_id=...`，服务端从已知记录解析目标，不能跨机器人读取；每页最多 40 条问答记录。主动与定时发送通过服务端外部消息 ID 前缀判定，只展示机器人发出气泡，不把后台标识当成用户发言。失败、处理中与送达未知明确显示。历史图片/语音仅有摘要和处理信息，提示原文件未保存，不伪造可播放资源。

底部文字发送复用原 POST /send，以机器人身份发送到 QQ，不调用聊天模型。草稿和请求 UUID 按目标保存，网络结果未知时保留原内容和 UUID，只允许查询同一请求结果或明确开始新消息。图片/语音使用原发送窗口，默认音色仍跟随机器人配置。所有消息按文本渲染，不执行消息中的 HTML。前端新增 conversation.js / conversation.css，无数据库迁移；后端重启及后台刷新后生效，按约定不运行测试、不打开浏览器、不真实发送。

## 对话头像（已实现，真实头像待验收）

私聊列表与历史消息中的发送者头像，使用所属机器人的公开 AppID 和记录 user_id（私聊 user_openid、群成员 member_openid）拼接 `https://q.qlogo.cn/qqapp/{AppID}/{OpenID}/640`。这是社区使用方式，当前官方消息事件未直接提供发送者 avatar，地址可用性不作保证；QQ 返回默认图时无法自动识别。群会话仍显示“群”占位，不把成员头像当群头像。加载失败回退姓名首字；机器人气泡复用官方资料头像，失败回退机器人名称首字。
