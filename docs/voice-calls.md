## 通话错误诊断（代码已编写，待部署验证）

建立上游连接、配置会话及通话中断将分别提示所在阶段。供应商错误事件提取错误码和简短说明，隐藏当前通话供应商密钥，不输出完整事件、请求头或音频；WebSocket 关闭显示关闭码，不直接展示关闭原因。此改动不自动重拨或调用模型。

补充诊断（代码已编写，真实通话待验证）：本地校验使用专用异常显示固定中文原因；未知异常仅记录调用栈文件名、函数和行号，不记录局部变量、原始异常内容或请求数据，便于定位接通后立即失败的具体代码。

失败响应处理修复（代码已编写，待真实接口验证）：收到 `response.done` 的 `failed` 状态时先提取供应商错误并结束通话，不再先向已断开的上游发送清理请求，避免关闭码1011覆盖原始失败原因；其他取消状态继续沿用插话清理。

## 实时对话模式（本轮代码已编写，待联调）

新增供应商类型 `realtime`，适配 `qwen-audio-3.1-realtime-flash`；通话配置增加 `mode`（默认 `pipeline`，可选 `realtime`）、`realtime_provider_id` 和独立音色 `realtime_voice`（默认 `longanqian_v3.1`）。实时模式直接使用一个模型收发语音，不调用独立 ASR、chat 或 TTS；旧配置保持原模式。

接通时发送机器人人设、独立通话提示词及少量网页记忆；模型通过 `search_memory` 工具在通话中查询最新记忆。记忆按机器人和服务端管理员账号摘要隔离，不读取 QQ 私聊、群聊或主人记忆。页面提供显式保存和删除入口；通话中可以保存新记忆，之后工具查询即可读到；删除要求先挂断，避免上游上下文继续引用旧内容。首版不自动提取长期记忆，也不把模型口头“记住了”当成数据库写入。

新增手写迁移 `0025_realtime_calls`，在0024之后扩展通话配置并建立独立网页记忆表。部署前停服务、备份并显式迁移，应用不自动升级。本轮不执行迁移、部署、测试、浏览器或付费通话。协议依据：[百炼 WebSocket](https://help.aliyun.com/en/model-studio/fun-audiochat-realtime-websocket-api)、[客户端事件](https://help.aliyun.com/en/model-studio/fun-audiochat-client-events)、[服务端事件](https://help.aliyun.com/en/model-studio/qwen-audio-realtime-server-events)。

实时模式单独记录模型实际返回用量；生成完成与浏览器确认播放分开。插话立即停播并取消生成，丢弃旧响应音频；对未确认播放的输出从上游上下文删除，防止当成已听见的回复。工具查询有超时和次数限制，不自动重试付费调用。

## 范围与入口

后台新增独立「语音通话」菜单，仅登录管理员使用。选择机器人后开始通话，支持麦克风静音、实时转写、流式回答及播报、手动和说话打断、挂断。通话不向 QQ 发送消息，不依赖 QQ 在线状态，不冒用 QQ 用户身份。每次通话独立上下文，复用机器人人设；组合模式不接入长期记忆；实时模式使用上述独立网页记忆，QQ 身份互通不在本版范围。

## 供应商设计

沿用「模型供应商」统一管理模型、地址和加密密钥，不另建一套通话供应商表。现有每条供应商代表一个模型配置，保持不变。

| 类型 | 用途 | 通话选择 |
| --- | --- | --- |
| chat | 普通文字模型 | 允许独立选择，留空跟随机器人/全局默认 |
| asr | 完整录音识别，含 Filetrans | 禁止作为实时识别模型 |
| asr_realtime | 实时语音识别 | 本次新增，适配百炼 Qwen 实时识别协议 |
| tts | 语音合成 | 复用现有 Qwen Realtime 配置，增加流式输出 |
| realtime | 端到端实时语音对话 | qwen-audio-3.1-realtime-flash，独立音色，无需 ASR/TTS |
| image | 图片生成配置 | 与通话无关 |

通话配置按 bot_id 单独保存启用开关、三个供应商选择、音色、时长及空闲限制。保存和开始通话均校验类型、启用状态、密钥与支持协议。修改被引用供应商的类型或停用时要求先调整通话配置。供应商修改下一次通话生效，进行中通话使用开始时快照。不同模型可使用同一个服务商账号，但不把实时能力自动赋给现有录音模型。

## 音频与轮次

浏览器 AudioWorklet 采音并重采样为 ASR 所需 PCM，通过同源 WebSocket 传送；实时 ASR 的终稿触发聊天模型流式调用，文本按短句交给 TTS，返回 PCM 后持续播放。保持有限音频队列，积压时报错结束，不能无限增加延迟。

每轮携带 turn_id，打断时取消旧生成、清空客户端播放队列并丢弃迟到结果。记录客户端确认播放完成的句子作为后续上下文依据；未确认内容不当作完整传达。客户端播放确认不证明实际听见。启用浏览器回声消除和降噪，真实扬声器回声仍需人工验收。

聊天上下文与 QQ 的 ChatService 锁隔离，不让通话占用 QQ 队列。默认全局一通电话，最长15分钟，空闲60秒，所有外部调用有限时、不自动重试付费操作。挂断、断线、登录失效时关闭上游连接及后台任务。

## 鉴权与记录

创建会话复用管理员登录、来源和 CSRF 校验；WebSocket 校验同源、Cookie、一次性短期票据及会话归属。票据不放 URL。定期复查登录，退出后停止通话。密钥不传浏览器，不写日志。

新增手写迁移 `0023_voice_calls`，按机器人保存配置、通话元数据及轮次文本/中断/用量。默认不保存原始音频。只记录聊天模型实际返回的用量，取消或异常造成用量缺失保持未知；ASR/TTS 暂未提取用量，不自动混入 QQ Token 统计。

1. 停止服务、备份项目库后执行 `python -m alembic upgrade head`，目标版本为 `0023_voice_calls`（依赖0022）。本次不自动执行。
2. 重启服务并刷新后台。在「模型供应商」选择千问预设，新增 `asr_realtime` 类型，默认模型 `qwen3-asr-flash-realtime`，填写对应地域密钥并启用。保存只检查配置，不证明实际权限可用。
3. 准备已有 chat 模型和 `qwen3-tts-flash-realtime` TTS 模型；识别和合成的服务地址默认 `https://dashscope.aliyuncs.com`，其他地域须配套域名和密钥。
4. 打开「语音通话」，选择机器人，绑定实时识别、合成及可选聊天模型，选择音色，启用并保存。
5. 点击「开始通话」，允许麦克风。自动结束话语并回复；静音会发送静音音频，仍占用通话连接。切换菜单、关闭页面或挂断会停止通话。退出登录的服务端复查间隔为5秒。
6. 在页面下方查看最近20次通话，可继续加载更早记录及文字详情。页面中的完整生成文本与“确认播完”文本分开，不把未播放内容当作已传达。

接口统一位于 `/api/admin/voice-calls`：`POST /` 创建票据、`DELETE /{call_id}` 挂断；`GET/PUT /config/{bot_id}` 读取/保存设置；`GET /history/{bot_id}` 及 `GET /history/{bot_id}/{call_id}` 查询记录；`/connect` 为 WebSocket。票据在首条消息传递，不进入地址栏或访问日志。

`voice_call_configs` 使用 bot_id 主键及供应商外键。`voice_calls` 保存通话ID、bot_id、UTC起止时间、状态、结束原因、模型名称快照及轮次 JSON 文本；不含供应商密钥或原始音频。进程异常退出留下的 active/connecting 记录，查询时显示“异常中断，结束时间未知”，不伪造结束时间。历史不用于恢复通话。

硬性预算：全局1路；待接通预留30秒；每次最多100轮；连续说话最多60秒；每轮聊天最多512 token、600字符、16次短句合成；单轮生成及播报合计120秒；TTS每句45秒；等待播放确认40秒；音频上传积压和播放积压超限即停止。配置允许最长60～1800秒、空闲30～300秒，默认900/60秒。无自动重拨或付费重试，也不套用普通聊天备用模型。断开本地连接不承诺供应商立即停止计费。

实时识别目前仅适配 Qwen3-ASR-Flash-Realtime 家族，未宣称支持所有名称带 realtime 的模型。协议依据：[客户端事件](https://help.aliyun.com/en/model-studio/qwen-asr-realtime-client-events)、[服务端事件](https://help.aliyun.com/en/model-studio/qwen-asr-realtime-server-events)。输入16kHz单声道16位PCM，识别草稿由 text + stash 展示，completed.transcript 才进入聊天；服务端 VAD 停顿阈值600ms。TTS输出24kHz PCM，不逐块添加首尾静音。

### 实时模式使用与边界

1. 停服、备份后显式升级到0025，重启并刷新后台。
2. 在供应商添加 Qwen 预设、realtime 类型，填写密钥并启用。
3. 「语音通话」选择实时语音对话，选择该供应商，音色默认 longanqian_v3.1，保存后拨号。
4. 页面“网页通话记忆”可保存当前管理员的笔记。通话中保存后询问相关事项，模型可查询最新记录；没有自动提取或语音写入工具。删除须先挂断。

实时模式使用 server_vad（600ms），输入16kHz/输出24kHz单声道16位PCM。每通话最多100个模型响应（工具续答也计入），每响应1200字符/90秒音频/120秒生成及播放确认，最多30次记忆查询、每响应3个工具请求。音频队列64块，积压超限终止，不无限缓存；工具结果最多8条/2400字，单次数据库查询12秒超时。未知用量不估算。当前完整响应播完才确认，中途听到的部分不作精确转写对齐。

新增入口：`qbot/voice_call_realtime.py`、`qbot/prompts/voice_realtime.txt`；记忆管理接口为 GET/POST `/api/admin/voice-calls/memories/{bot_id}` 和 DELETE `/api/admin/voice-calls/memories/{bot_id}/{memory_id}`，沿用管理员身份、同源及写入CSRF校验。全部网页身份范围由后端确定。
