## 持久化记忆接入（2026-10-30，代码已编写，待验收）

启用后台记忆后，RecordedChat 在生成前读取当前范围的摘要、长期条目、同群主人参考及最近24小时最多10轮成功回复；持久历史替代当前内存历史，保留已存转写和视觉说明，分别限制字节预算。未启用时保持原有内存策略。显式 `/remember`、`/memory`、`/memory-edit`、`/forget`、`/remember-group` 不调用模型，持久化成功后才反馈；`/reset` 推进数据库恢复边界并保留长期记忆。

接收时同事务登记来源及可信主人版本，应用级异步 worker 增量整理；整理模型独立、无备用切换、最多30秒且不自动重试。群聊默认仅主人参与自动长期提取，普通成员只生成必要摘要。身份/人设变化、遗忘及主人切换使相应旧任务和历史失效，在途回复与管理写入串行。完整规则和首版限制见[记忆系统](memory-system.md)。需先显式迁移至0024；未运行测试、数据库迁移、浏览器或真实模型/QQ验收。下文内存行为说明适用于未开启记忆的模式。

## QQ 消息流程

1. WebSocket / Webhook 接收群聊 @ 消息或 C2C 私聊，转换为统一消息对象。
2. Dispatcher.accept 检查时间、去重、限流和队列容量；后台模式先持久化记录再入队。
3. Dispatcher.run 顺序取出消息，检查排队期限，后台模式预处理文字、表情及附件。
4. RecordedChat 读取当前机器人绑定的聊天供应商或全局默认；有图片时先调用独立视觉模型生成摘要。
5. 读取管理员绑定身份，ChatService 组装人设、身份、历史、当前文字及视觉摘要并调用模型。
6. 保存生成结果，再由发送回调选择文字或语音。回调成功后才更新内存历史，最后保存记录状态。

每个机器人独立顺序消费，ChatService 锁覆盖生成和发送。当前没有工具调用循环。附件全部失败且无可用文字时直接报告原因，不调用聊天模型。

## 提示词与配置

提示词顺序：系统人设 → 可选身份信息 → 多模态数据边界说明 → 历史 → 当前用户消息。视觉摘要作为用户资料进入当前消息；原图只交给视觉模型，后续历史不保留原图。README、AGENTS.md 和模块文档不进入业务提示词。

后台每次请求从数据库读取供应商并解密密钥，创建模型，结束后关闭客户端；供应商修改下次请求生效。机器人人设在运行实例创建时加载，保存机器人重载对应实例；默认 system.txt 修改后需重启或重载。无后台模式使用环境变量，后台缺少供应商时不回退到环境凭证。

本地 chat 复用聊天服务，但不经过 QQ 附件和发送流程。

网页「语音通话」使用独立轮次控制和内存上下文，复用 provider_model 与机器人人设，不持有 QQ ChatService 的锁，也不继承 QQ 身份或历史。独立流式生成使用客户端确认播完的片段构造后续历史；尚无持久化记忆和工具循环，详见[语音通话](voice-calls.md)（已编写，真实联调待验收）。

## 会话与时限

聊天模型输出上限默认改为 4096 token，可通过 MODEL_MAX_TOKENS 配置；已有环境文件中的显式值会覆盖默认值，部署时需同步修改。超时与回复字符截断仍沿用现有配置。本次配置已修改，未调用真实模型验证。

先按 bot_id 运行实例隔离，再按来源、群和用户隔离。默认闲置 1800 秒过期、保留最近 10 轮、最多 1000 个会话，具体配置见 config.py。`/reset` 清空当前会话，不删除数据库记录；重载机器人和进程重启会清空对应内存历史。

家庭身份按 bot_id + user_id 共享，身份变化后下一次对话清理该会话旧身份上下文；身份角色不授予管理权限。数据库记录尚不用于重启恢复模型历史或重放队列。

聊天客户端读取 MODEL_TIMEOUT_SECONDS，默认 120 秒；后台只覆盖重试次数为 0，不再写死 45 秒。ChatService 的 CHAT_TIMEOUT_SECONDS 默认也为 120 秒，已有环境文件需同步修改。QQ 主流程仍最多 120 秒（含排队和媒体处理），并受平台回复窗口约束，因此模型实际可用时间可能少于 120 秒。视觉、ASR、TTS 子时限见[多模态](multimodal.md)。本次仅静态核对，未进行真实模型超时验收。

## 排查与修改

查不到接收记录先读[QQ 接入](qq-runtime.md)；有记录但回复异常，按 Dispatcher → RecordedChat → ChatService → 模型配置排查。区分 expired、model_failed、send_failed、delivery_unknown；网络超时不等于未送达，发送开始后不盲目补发。

用量只记录实际返回值，缺失保持未知，输入与输出均有值时可相加；不估算费用。持久化和汇总见[存储](storage.md)。

## 认主与意见优先级（已编写，待验证）

后台选择唯一主人后，每次对话注入当前主人和发送者是否为主人的可信标识。主人的明确要求优先于其他人的意见、默认人设和玩笑；其他人不能取消、替换或代传主人指令。未知主人意见不编造，主人改变意见以最新明确要求为准。身份不额外授予管理或工具权限。

为处理同群不同成员的意见冲突，额外读取当前群中、认主之后且最近 30 分钟内主人已成功回复的最近 5 条文字（每条最多 800 字），以独立参考消息提供，不合并用户会话历史，不读取私聊或其他群。转述和引用不能冒充主人原话。窗口外要求不保证记住，不自动提取永久指令。切换或取消主人会在下一次请求清理旧身份上下文；同群参考消息变化不清空会话。

## 普通聊天天气与时间（代码已编写，待验证）

QQ 私聊、群聊及本地 ChatService 回复统一注入当前北京时间；当前问题涉及天气、气温、降雨、带伞或冷热时，复用 greeting_context.py 的 Open-Meteo 查询，默认仅提供石家庄当前天气和当天预报。天气话题的简短追问参考同会话最近一条用户消息触发查询，不读取其他会话。不是模型自主工具调用，不新增模型请求。

查询受聊天总超时及原天气模块5秒上限约束，不重试，成功最多缓存10分钟、失败缓存1分钟。失败时明确说明暂时查不到，不使用旧聊天中的天气补全；其他城市、未来日期、空气质量和风速不在当前数据范围内。天气参考只用于本次请求，不写入会话原始输入；回复中的天气也不能充当后续实时数据。网页语音通话不在本次接入范围。无新增配置、依赖或数据库迁移。
